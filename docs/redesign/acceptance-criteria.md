# Acceptance Criteria — Step 02

> วันที่: 2026-10-14 · รูปแบบ Given / When / Then
> **Env:** ทุก AC ที่เขียนข้อมูลต้องทดสอบบน **staging** เท่านั้น (ห้ามทดสอบบน Production)
> **TZ:** เวลาในตัวอย่างเป็น Asia/Bangkok (UTC+7) เว้นแต่ระบุไว้
> **Test type:** U = unit, I = integration (DB/RLS บน staging), E = E2E/manual ตาม CUJ, A = accessibility tooling
> ค่าที่มีเครื่องหมาย † เป็นค่าที่เสนอ และต้องยืนยันใน `product-decisions.md`

## E1 — Access

**AC-01-1** (E) Given ผู้ใช้มีบัญชีที่ใช้งานได้ When กรอกอีเมลและรหัสผ่านถูกต้องแล้วกดเข้าสู่ระบบ Then ไปหน้า Dashboard ภายใน 3 วินาที † และไม่มี error
**AC-01-2** (E) Given รหัสผ่านผิด **หรือ** อีเมลไม่มีในระบบ When กดเข้าสู่ระบบ Then เห็นข้อความเดียวกัน "อีเมลหรือรหัสผ่านไม่ถูกต้อง" และปุ่มกลับมากดได้
**AC-01-3** (E) Given เลือก "จดจำอีเมลไว้" แล้ว login สำเร็จ When เปิดหน้า login ใหม่ Then ช่องอีเมลถูกเติมไว้และช่องรหัสผ่านว่าง
**AC-02-1** (E) Given ไม่มี session When เปิด `/`, `/add`, `/history` Then ถูกพาไป `/login`
**AC-02-2** (I) Given ใช้แค่ anon key (ไม่มี session) When `select`/`insert`/`update`/`delete` ตาราง `records` หรือ `expenses` ผ่าน REST Then ได้ 0 แถวหรือถูกปฏิเสธทุกคำสั่ง
**AC-02-3** (I) Given การตั้งค่า Auth ของ project When เรียก sign-up API ด้วยอีเมลใหม่ Then ถูกปฏิเสธ
**AC-03-1** (E) Given login อยู่ When กด logout Then ไป `/login` และกด back แล้วไม่เห็นข้อมูล

## E2 — Recording

**AC-04-1** (E) Given อยู่หน้าบันทึกรายรับ When เลือก "ล้างรถ", กรอกทะเบียน "กข 1234", ราคา 150, เลือกประเภทรถ แล้วกดบันทึก Then มี record ใหม่ 1 แถว: `type='wash'`, `plate='กข 1234'`, `price=150`, `payment_status='paid'` (ค่าเริ่มต้น) และ `created_at` เป็นวันที่ที่เลือกกับเวลาปัจจุบัน
**AC-04-2** (U) Given ทะเบียนว่าง หรือยาว 21 ตัวอักษร หรือไม่เลือกประเภทรถ หรือราคาว่าง When กดบันทึก Then ไม่มีการเขียน DB และเห็นข้อความบอกช่องที่ผิดเป็นภาษาไทย
**AC-04-3** (E) จำนวนการแตะเพื่อบันทึกรถล้าง 1 คัน (ไม่นับการพิมพ์ทะเบียนและราคา) ต้องไม่มากกว่า baseline ที่วัดใน Step 03
**AC-05-1** (E) Given บันทึกด้วยโหมด "บันทึกแล้วทำต่อ" When บันทึกสำเร็จ Then ทะเบียน, ราคา, ชื่อลูกค้า และหมายเหตุถูกล้าง แต่ประเภทงาน, ประเภทรถ, ยี่ห้อ, สถานะชำระ และวันที่ยังคงค่าเดิม และเห็นข้อความสำเร็จที่มีทะเบียน
**AC-06-1** (E) Given กดบันทึก When กดซ้ำ 3 ครั้งเร็ว ๆ ระหว่างรอ Then มี record ใหม่ 1 แถวเท่านั้น
**AC-07-1** (I) Given บันทึกรายการ `payment_status='unpaid'`, `customer_name='เต็นท์ A'` When เปิดสมุดทวงหนี้ Then รายการอยู่ในกลุ่ม "เต็นท์ A"
**AC-08-1** (I) Given มี record ทะเบียน "กข 1234" อยู่ 2 รายการ When พิมพ์ทะเบียนนี้ในฟอร์ม Then เห็น "ลูกค้าประจำ! เข้ามาครั้งที่ 3" ภายใน 1 วินาทีหลังหยุดพิมพ์
**AC-09-1** (E) Given เคยบันทึกชื่อลูกค้า 4 ชื่อบนเครื่องนี้ When เปิดฟอร์มรายรับ Then เห็น quick-pick 3 ชื่อล่าสุด และ autocomplete แสดงได้สูงสุด 30 ชื่อ
**AC-10-1** (E) Given โหมดรายจ่าย When แตะปุ่มลัด "ค่าน้ำยา" กรอก 300 แล้วบันทึก Then มี expense `title='ค่าน้ำยา'`, `amount=300`
**AC-10-2** (U) Given จำนวนเงินว่างหรือ 0 หรือรายการว่าง When บันทึก Then ไม่มีการเขียน DB และเห็นข้อความเตือน
**AC-11-1** (E) Given เลือกวันที่เมื่อวาน When บันทึกตอน 10:15 Then `created_at` = เมื่อวาน 10:15 (+07:00) และรายการไม่ปรากฏในยอด "วันนี้"
**AC-11-2** (A) วันที่เปลี่ยนได้ด้วยคีย์บอร์ดอย่างเดียว (Tab → Enter/Space → เลือก)
**AC-12-1** (E) Given กรอกทะเบียนและราคาแล้วแต่ยังไม่บันทึก When reload หน้า หรือ pull-to-refresh Then ยังอยู่หน้าเดิม และค่าที่กรอกยังอยู่
**AC-12-2** (E) Given บันทึกสำเร็จ When reload Then ฟอร์มว่าง (draft ถูกล้างหลังบันทึก)
**AC-13-1** (I) Given หมายเหตุ "ราคา <500 & ส่วนลด" When บันทึกแล้วเปิดดูในประวัติ, บิล PDF และ Excel Then แสดง "ราคา <500 & ส่วนลด" ตรงตามที่พิมพ์ และไม่มีสคริปต์ทำงาน
**AC-13-2** (U) Given ข้อความ `<img src=x onerror=alert(1)>` When แสดงผลในทุกหน้า Then แสดงเป็นข้อความ และไม่มี script ทำงาน

## E3 — Dashboard

**AC-14-1** (U) Given วันนี้มีรายรับ paid 500, unpaid 300 และรายจ่าย 200 Then เงินสดสุทธิ = 300, รายรับรวม = 800, รายจ่าย = 200 (กติกาเดิม FR-DASH-01)
**AC-14-2** (U) Given เมื่อวานรายรับรวม 400 และวันนี้ 800 Then แสดง ▲100%, และถ้าเมื่อวาน = 0 แสดง 0% (กติกาเดิม)
**AC-14-3** (U) Given เครื่องตั้ง timezone เป็น UTC When เวลา 01:00 ของวันที่ 15 (เวลาไทย) Then "วันนี้" คือวันที่ 15 ตามเวลาไทย (FR-PLAT-05)
**AC-15-1** (U) Given สลับ 7 วัน/30 วัน Then กราฟมี 7/30 แท่งตามลำดับ โดยแท่งสุดท้ายคือวันนี้
**AC-16-1** (U) Given ลูกค้าที่มีชื่อ 6 รายที่มียอดเดือนนี้ Then แสดง 4 รายที่ยอดเดือนสูงสุด และอีก 2 รายรวมเข้ากับ "ลูกค้าทั่วไป" (กติกาเดิม) โดยยอดรายปีรวมรายการค้างชำระ
**AC-16-2** (I) Given ลูกค้ามีรายการในปีนี้ 1,500 แถว Then ยอดรายปีเท่ากับผลรวมจาก SQL ของทั้ง 1,500 แถว
**AC-17-1** (E) Given มีรายการวันนี้ When แตะการ์ด Then เปิดหน้าแก้ไขรายการเดียวกับในประวัติ และบันทึกแล้วตัวเลขบน dashboard อัปเดต
**AC-18-1** (E) Given เปิด dashboard 2 เครื่อง When เครื่อง A บันทึกรายการ Then เครื่อง B เห็นยอดใหม่ภายใน 5 วินาที † โดยไม่ต้องกดรีเฟรช
**AC-19-1** (E) Given ตั้งพิกัดเป็นจังหวัดอื่น Then ชื่อพื้นที่ที่แสดงตรงกับที่ตั้งไว้
**AC-19-2** (E) Given API อากาศล่ม Then ส่วนอื่นของ dashboard ยังใช้งานได้ปกติ

## E4 — Debt

**AC-20-1** (U) Given รายการค้างชำระของ "เต็นท์ A" 3 รายการ (ค้าง 2, 8, 15 วัน) Then กลุ่มแสดงยอดรวม, "3 คัน", "ค้างนานสุด 15 วัน" และระดับความเร่งด่วนสูงสุด
**AC-20-2** (A) ระดับความเร่งด่วนสื่อด้วยข้อความหรือไอคอนที่มีชื่อ ไม่ใช่สีอย่างเดียว
**AC-21-1** (E) Given กลุ่ม "เต็นท์ A" When กดสร้างบิล Then ได้ PDF ที่มีชื่อร้าน, ชื่อลูกค้า, รายการทุกคันพร้อมวันที่, ยอดรวม และยอดเป็นตัวอักษรไทยที่ถูกต้อง (เช่น 1,250 → "หนึ่งพันสองร้อยห้าสิบบาทถ้วน")
**AC-22-1** (E) Given กด "เคลียร์ยอด" ของ "เต็นท์ A" Then เห็น dialog ที่ระบุจำนวนรายการและยอดเงินที่จะเคลียร์ โดยมีปุ่มยืนยันและยกเลิกที่ใช้คีย์บอร์ดได้
**AC-22-2** (I) Given กลุ่ม "ลูกค้าทั่วไป (ไม่ระบุชื่อ)" มีรายการ `customer_name` = `NULL`, `''` และ `'  '` When ยืนยันเคลียร์ยอด Then ทั้ง 3 รายการเป็น `paid` และกลุ่มหายไปหลัง refresh
**AC-22-3** (I) Given มีรายการค้างของ "เต็นท์ A" และ "เต็นท์ B" When เคลียร์ "เต็นท์ A" Then รายการของ "เต็นท์ B" ไม่เปลี่ยน
**AC-23-1** (I) Given ออกบิลจากเครื่อง X และ Y สลับกัน 4 ใบ Then เลขที่บิลทั้ง 4 ใบไม่ซ้ำกัน (ขึ้นกับ Q-05)

## E5 — History & Edit

**AC-24-1** (I) Given ปีที่เลือกมี 3,000 รายการ When เลือก "ตลอดทั้งปี" Then ยอดรวมและจำนวนเท่ากับ SQL `sum`/`count` ของทั้งปี
**AC-24-2** (U) Given เลือกเดือนมีนาคม Then แสดงเฉพาะรายการที่ `created_at` อยู่ในเดือนมีนาคมตามเวลาไทย
**AC-25-1** (U) Given ค้นหา "กข" Then เห็นรายการที่ทะเบียน **หรือ** ชื่อลูกค้ามี "กข" (ไม่สนตัวพิมพ์เล็ก/ใหญ่)
**AC-25-2** (U) Given กรองวันที่ 14 ถึง 14 Then รวมรายการเวลา 00:30 และ 23:45 ของวันที่ 14
**AC-26-1** (U+E) Given รายการ `created_at = 2026-10-14T03:30+07:00` When เปิดแก้ไขแล้วบันทึกโดยไม่แก้อะไร Then `created_at` ไม่เปลี่ยน และทดสอบซ้ำที่ 00:00, 06:59, 07:00 และ 23:59
**AC-26-2** (U) Given ลบราคาจนว่าง หรือลบทะเบียนจนว่าง When บันทึก Then ไม่บันทึก และเห็นข้อความเตือน (กติกาเดียวกับ AC-04-2/AC-10-2)
**AC-26-3** (E) Given กดบันทึกการแก้ไข When กดซ้ำระหว่างรอ Then เกิดการ update 1 ครั้ง และปุ่มแสดงสถานะกำลังบันทึก
**AC-26-4** (U) Given รายการเก่าที่ `services` = `['รถเก๋ง', 'TOYOTA', 'ล้างห้องเครื่อง']` When เปิดแก้ไข Then ประเภทรถ, ยี่ห้อ และหมายเหตุถูกเลือกหรือเติมถูกต้อง
**AC-27-1** (E) Given กดลบ Then ต้องยืนยันอีกครั้งก่อนลบ และหลังลบรายการหายจากรายการและยอดรวม
**AC-28-1** (I) Given ลบรายการแล้ว When กด "กู้คืน" ภายในเวลาที่กำหนด † Then รายการกลับมาพร้อมค่าเดิมทุก field (ขึ้นกับ Q-02)
**AC-29-1** (I) Given ผู้ใช้ A สร้าง และผู้ใช้ B แก้ไข Then "เพิ่มโดย" = A และ "แก้ไขล่าสุดโดย" = B
**AC-29-2** (I) Given client ส่ง `created_by_email` ปลอมมาใน insert Then ค่าที่บันทึกจริงเป็นอีเมลของ session (NFR-SEC-03)

## E6 — Export

**AC-30-1** (I) Given ช่วงเดือนที่มี 2,500 รายรับและ 400 รายจ่าย When export โหมดธนาคาร Then ไฟล์มี 2,500 + 400 แถวข้อมูล และยอดรวมในไฟล์เท่ากับ SQL
**AC-30-2** (E) ทั้งสองโหมดมี **ข้อมูลทุก field** ที่ไฟล์จาก v1.0.0 มี (เทียบกับข้อมูลชุดเดียวกันบน staging) และยอดรวมเท่ากัน ส่วนลำดับคอลัมน์, การจัดรูปแบบ และชื่อ sheet ปรับได้ (D-16)
**AC-31-1** (I) Given query รายจ่ายล้มเหลว (จำลองบน staging) When export Then ไม่มีไฟล์ถูกดาวน์โหลด, เห็นข้อความ error ภาษาไทย และปุ่มกลับมากดได้

## E7 — Accessibility & Usability

**AC-32-1** (A) viewport meta ไม่มี `user-scalable=no` และ `maximum-scale=1` และ pinch-zoom ได้ถึง 200% โดยเนื้อหาไม่ถูกตัด
**AC-32-2** (A) ไม่มีข้อความเนื้อหาที่เล็กกว่าค่าขั้นต่ำใน NFR-A11Y-03 †
**AC-33-1** (A) ทุกปุ่มและลิงก์มีพื้นที่แตะ ≥ 44×44px †
**AC-34-1** (A) axe-core ทุกหน้า (login, dashboard, add, history, ทุก modal) มี serious/critical = 0
**AC-34-2** (E) ทำ CUJ-2, CUJ-3, CUJ-6 ได้ด้วยคีย์บอร์ดอย่างเดียว และ modal กัก focus แล้วคืน focus เมื่อปิด
**AC-35-1** (E) Given ตัดเน็ตแล้วกดบันทึก Then เห็นข้อความไทยว่าบันทึกไม่สำเร็จ ให้ตรวจอินเทอร์เน็ต ไม่มีข้อความภาษาอังกฤษจากระบบ และข้อมูลในฟอร์มยังอยู่

## E8 — Engineering Safety

**AC-36-1** (E) Given เปิด Preview deployment Then เห็นป้ายบอก environment และ Supabase project ref ≠ production
**AC-36-2** (I) Given build Preview ด้วย env ที่ชี้ production project ref Then build หรือ runtime ล้มทันทีพร้อมข้อความชัดเจน
**AC-37-1** (E) Given PR ที่มี type error Then CI fail และ merge ไม่ได้
**AC-38-1** (E) Given เกิด error ฝั่ง client บน staging Then error ปรากฏในระบบ monitoring ภายใน 5 นาที † และไม่มีข้อมูลลับหรืออีเมลผู้ใช้ใน payload
