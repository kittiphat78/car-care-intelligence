## 2. Visual Direction: "สมุดบัญชีร้านที่ชัดเจน" (Clear Ledger)

ความรู้สึกที่ต้องการ: **เรียบ, มั่นคง, อ่านง่าย, เชื่อถือได้** เหมือนแอปธนาคารที่ดี ไม่ใช่แอปเกม

| มิติ | ทิศทาง | เลิกใช้จากของเดิม |
|---|---|---|
| สี | พื้นกลาง (neutral) + สีหลักน้ำเงินเข้มสีเดียว และสีอื่น **ใช้เพื่อสื่อความหมายเท่านั้น** (รายรับ, รายจ่าย, ค้างชำระ, ประเภทงาน) | gradient ม่วง-คราม, gradient แดงกะพริบ, สี Tailwind ตรง ๆ |
| ตัวเลข | ตัวเลขเงินคือพระเอก: ใหญ่ หนา ตัวเลขกว้างเท่ากัน และจัดชิดขวาในรายการ | ตัวเลขหลายขนาดปนกัน |
| พื้นผิว | การ์ดพื้นเรียบ ขอบบาง และเงาน้อย (light) หรือพื้นสว่างขึ้นตามระดับ (dark) | glassmorphism, backdrop-blur, เงาสีฟุ้ง |
| ไอคอน | ชุดเส้นเดียวกันทั้งระบบ (stroke 2px, มุมมน) ใช้คู่กับข้อความเสมอ | emoji เป็นไอคอนหลัก (คงไว้ได้เฉพาะ "ตกแต่ง" ที่ซ่อนจาก screen reader) |
| การเคลื่อนไหว | สั้นและมีเหตุผล (บอกสถานะหรือที่มา-ที่ไป) | float, bounce, pulse ต่อเนื่อง |
| ภาษา | ไทยสุภาพ สั้น ตรง และไม่ใช้ตัวพิมพ์ใหญ่ทั้งคำหรือ letter-spacing กว้างกับภาษาไทย | `uppercase tracking-widest` บนป้ายไทย |

### 2.1 Moodboard (คุณลักษณะอ้างอิง ไม่ใช่ภาพ)

| อ้างอิง | สิ่งที่หยิบมา |
|---|---|
| แอปธนาคารไทยยุคใหม่ (หน้าสรุปยอด) | ยอดเงินเด่นบนสุด, รายการเรียงตามวัน และตัวเลขชิดขวา |
| แอป POS / บันทึกร้านค้า | ปุ่มเลือกใหญ่, การบันทึกต่อเนื่อง และ action bar ติดล่าง |
| เอกสารราชการไทย (ฟอนต์ Sarabun) | ความเป็นทางการ อ่านง่าย และเข้ากับบิล PDF ที่ใช้ Sarabun อยู่แล้ว |
| Dashboard การเงินบน PC | กริด 2 คอลัมน์, sidebar ซ้าย และตารางที่สแกนง่าย |

## 3. Design Principles

| # | หลักการ | วัดได้อย่างไร |
|---|---|---|
| DP-1 | **อ่านออกในครั้งเดียว:** ข้อความเนื้อหา ≥ 16px, ข้อความรอง ≥ 14px และ contrast AA ทั้ง 2 theme | `accessibility-guidelines.md` §2, ตาราง contrast ใน `design-tokens.md` §3.3 |
| DP-2 | **สีมีความหมายเดียว:** เขียว = เงินเข้า/ชำระแล้ว, แดง = เงินออก/อันตราย, ส้มอำพัน = ค้างชำระ, ฟ้า = ล้างรถ, ม่วง = ขัดสี และน้ำเงิน = action หลัก | ตาราง semantic tokens |
| DP-3 | **หนึ่งหน้าจอ หนึ่ง action หลัก:** ปุ่ม primary ไม่เกิน 1 ปุ่มต่อพื้นที่มองเห็น | review screen spec |
| DP-4 | **สถานะไม่พึ่งสีอย่างเดียว:** ทุก badge หรือสถานะมีข้อความหรือไอคอนที่มีชื่อ | NFR-A11Y-06 |
| DP-5 | **คงที่และคาดเดาได้:** component เดียวกันหน้าตาและพฤติกรรมเดียวกันทุกหน้า (ไม่มี 2 แบบเหมือน Add กับ Edit เดิม) | TD-08, design-to-code map |
| DP-6 | **มือโปรแต่ไม่หรูเกิน:** ไม่ใช้เอฟเฟกต์ที่ไม่สื่อความหมาย | ไม่มี gradient หรือ blur ใน tokens |
| DP-7 | **ข้อมูลไม่หาย ตัวเลขไม่หลอก:** loading หรือ error ไม่แสดง ฿0 | IS-4 |

## 5. ตัวอย่างการใช้สีบนหน้าจอหลัก (คำอธิบาย)

- **เงินสดสุทธิวันนี้:** ตัวเลขสี `text` (ไม่ใช่เขียว) เพื่อความนิ่ง และถ้าติดลบใช้ `expense` + เครื่องหมาย "−" + ข้อความ "ติดลบ"
- **รายรับรวม ▲12%:** ลูกศรและตัวเลขใช้ `success-text`/`danger-text` พร้อมคำว่า "เพิ่มขึ้น" หรือ "ลดลง" ใน aria-label
- **การ์ดค้างชำระ:** พื้น `warning-subtle`, ยอด `warning-text` และไม่กะพริบ
- **รายการ:** แถบซ้ายบางสีตามประเภทงาน (ฟ้า/ม่วง) และ badge "ค้างชำระ" สีอำพันพร้อมข้อความ
- **ปุ่มเคลียร์ยอด:** `success` (เขียวเข้ม #047857 ตัวขาว 5.48:1) แทน emerald-500 เดิม (2.54:1)
