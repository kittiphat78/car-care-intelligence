## สิ่งที่เกิดขึ้น

ถ้ากดเข้าสู่ระบบก่อนหน้า login โหลดเสร็จ (เครื่องช้าหรือเน็ตช้า แล้วกด Enter หรือแตะปุ่มเร็ว) เบราว์เซอร์จะส่งฟอร์มแบบ GET ทำให้อีเมลและรหัสผ่านไปอยู่ใน URL ของหน้า `/login` [V จากการทดลองบน staging]

URL นั้นอาจถูกเก็บไว้ที่:
- **Vercel request logs** ของ production [I]
- **ประวัติของเบราว์เซอร์** บนเครื่องที่กด [I]
- ไม่ถูกส่งไปเว็บอื่น เพราะ `Referrer-Policy: origin-when-cross-origin` ส่งแค่ชื่อเว็บไปยังโดเมนอื่น [V header]

ไม่ทราบว่ามีใครเจอเหตุการณ์นี้จริงหรือไม่ [U]

## สาเหตุ

O-01 ใน Step 09 ทำให้ฟอร์ม login มาพร้อม HTML ตั้งแต่แรก (เพื่อให้เร็วขึ้น) แต่ฟอร์มไม่มี `method="post"` และไม่ได้ปิดปุ่มไว้ระหว่างรอ JavaScript · test ใน CI ใช้ Chromium ที่เร็วพอจึงไม่เห็น

## การแก้

- PR #47 (hotfix เข้า `main` ด้วยการอนุมัติของเจ้าของ):
  - `method="post"`
  - ปุ่มส่งปิดไว้จนหน้าพร้อม
  - ช่องที่กรอกไว้ไม่หาย
  - ฟอร์มบันทึกได้การป้องกันเดียวกัน
- ตรวจแล้วว่า production HTML มี `method="post"` [V]
- test ใหม่ (กันไม่ให้ script โหลดแล้วกด Enter): ล้มกับ `252f081` และผ่านกับ `4162c44` [V]
- release v2.1.0 ยังมีการแก้นี้ (`smoke-test-results.md` §1) [V]

## การตรวจย้อนหลัง

- 2026-10-19 ~23:50 เจ้าของเปิด Vercel → Logs แล้วเลือกช่วงเวลาย้อนไปถึง 05:05–20:12 ไม่ได้ · แผน Hobby ดูได้แค่ 30 นาทีล่าสุด ช่วงที่ยาวกว่าต้องเสียเงิน [V]
- จึง**ยืนยันไม่ได้**ว่ามีรหัสผ่านอยู่ใน log หรือไม่ · ไม่พบ log ไม่ได้แปลว่าปลอดภัย [U]
- log ที่ดูย้อนไม่ได้ อาจยังถูกเก็บไว้ที่ Vercel ตามนโยบายของ Vercel [U]

## งานที่ยังค้าง (เจ้าของ)

1. **เปลี่ยนรหัสผ่าน**ของบัญชีที่ login บน production ในช่วง 05:05–20:12 · ใช้เวลาไม่นาน และปิดความเสี่ยงที่ตรวจไม่ได้
2. ลบประวัติเบราว์เซอร์ที่มี `/login?email=` บนเครื่องในร้านที่ใช้ช่วงนั้น
3. ปิด incident เมื่อทำข้อ 1 แล้ว

## บทเรียน

- งานที่ merge เข้า `main` ขึ้น production ทันที → ตอนนี้งานปกติต้องผ่าน `develop` → release → RC ก่อน (S10-01)
- ต้องทดสอบบน WebKit/เครื่องช้าด้วย ไม่ใช่ Chromium อย่างเดียว ก่อน release (Step 10 ทำแล้ว · ยังไม่อยู่ใน CI)
- ฟอร์มที่มาพร้อม HTML ต้องมี `method="post"` และต้องปิดปุ่มส่งไว้จนหน้าพร้อมเสมอ
