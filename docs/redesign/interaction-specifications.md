## 2. Form Behavior

### 2.1 Input ตามชนิดข้อมูล

| ข้อมูล | ชนิด input | พฤติกรรม |
|---|---|---|
| ทะเบียน | text, `autocapitalize="characters"`, `autocomplete="off"`, `enterkeyhint="next"` | แปลงเป็นตัวพิมพ์ใหญ่ขณะพิมพ์ (คงเดิม) และตัดช่องว่างหัวท้ายตอนบันทึก |
| ราคา, จำนวนเงิน | text + `inputMode="numeric"` | รับเฉพาะตัวเลข (คงเดิม) และแสดงคั่นหลักพันขณะไม่ได้แก้ไข (เช่น 1,250) |
| วันที่ | native `<input type="date">` ที่ **มองเห็นและ focus ได้** หรือ custom picker ที่ใช้คีย์บอร์ดได้ | แสดงผลเป็น พ.ศ. (14/10/2569) และแก้ PP-13 |
| เวลา (หน้าแก้ไข) | `<input type="time">` 24 ชม. | ตีความเป็นเวลาไทยเสมอ (FR-PLAT-05) |
| ชื่อลูกค้า | text + รายการแนะนำ (ล่าสุด 30 ชื่อ) | quick-pick 3 ชื่อล่าสุดเป็นปุ่ม (คงเดิม) |
| ตัวเลือกเดียว (ประเภทงาน, ประเภทรถ, สถานะ) | กลุ่มปุ่มแบบ radio (`role="radiogroup"` + ลูกศรเลือก) | ประเภทรถแตะซ้ำแล้วยกเลิกได้ (คงเดิม) ส่วนประเภทงานและสถานะต้องมีค่าเสมอ |
| ยี่ห้อ | ค้นหา + ปุ่ม 8 ยอดนิยม + "ดูทั้งหมด (24)" | คงเดิม |
| ปุ่มลัดรายจ่าย | กลุ่มปุ่มที่เติมช่อง "รายการ" | แตะซ้ำแล้วล้าง (คงเดิม) |

### 2.2 Validation timing

1. **ก่อนกดบันทึกครั้งแรก:** ไม่แสดง error ยกเว้นเกินความยาว (นับตัวอักษรขณะพิมพ์ เมื่อเหลือ ≤ 10 ตัว)
2. **กดบันทึก:** validate ทุกช่องพร้อมกัน แล้วแสดง
   - **สรุปบนฟอร์ม** "กรุณาแก้ไข 2 ช่อง" ที่ลิงก์ไปแต่ละช่อง (`role="alert"`)
   - **ข้อความใต้แต่ละช่อง** ผูกด้วย `aria-describedby` และ `aria-invalid="true"`
   - เลื่อนและ focus **ช่องแรกที่ผิด**
3. **หลังจากนั้น:** แต่ละช่อง re-validate เมื่อออกจากช่องหรือเปลี่ยนค่า และ error หายทันทีเมื่อแก้ถูก
4. ช่องบังคับมี "\*" + ข้อความ "จำเป็น" สำหรับ screen reader และไม่ใช้สีอย่างเดียว

> ปัจจุบันแสดงแค่ error แรกท้ายฟอร์ม (PP-08) ซึ่งข้อนี้แก้

### 2.4 Action bar
- `/add`: แถบติดล่างจอเหนือ nav บน Compact/Medium และอยู่ท้ายฟอร์มบน Expanded
- ปุ่มหลัก "บันทึก" (ขวา, กว้างกว่า) และปุ่มรอง "บันทึกแล้วทำต่อ" (ซ้าย) **ลำดับคงเดิม** (`ActionButtons.tsx`)
- เมื่อ virtual keyboard เปิด แถบต้องไม่บังช่องที่กำลังพิมพ์ (ซ่อนแถบขณะ keyboard เปิดบนมือถือ หรือเลื่อนช่องขึ้นให้พ้น) และต้องทดสอบบน iOS Safari กับ Android Chrome (S03-05)
- Enter ในช่องสุดท้าย **ไม่** submit อัตโนมัติ (กันบันทึกพลาด) ส่วน `enterkeyhint="next"` เลื่อนไปช่องถัดไป

### 2.5 การคงค่าหลัง "บันทึกแล้วทำต่อ"
- คงค่า: ประเภทงาน, ประเภทรถ, ยี่ห้อ, สถานะ และวันที่ (FR-REC-05)
- ล้างค่า: ทะเบียน, ราคา, ชื่อลูกค้า และหมายเหตุ
- ค่าที่คงไว้ต้องเห็นชัดว่าถูกเลือก และถ้าสถานะคงเป็น "ค้างชำระ" ให้แสดงป้ายเตือนเล็ก "ยังเลือกค้างชำระอยู่"
- Focus ไปช่องทะเบียน

### 2.6 Draft (FR-REC-09)
ตาม UF-REC-05 เมื่อกู้ draft ให้แสดงแถบ "กู้ข้อมูลที่กรอกค้างไว้แล้ว" + ปุ่ม "ล้างฟอร์ม"

### 2.7 Edit dialog
- ใช้ component ฟอร์มชุดเดียวกับหน้าบันทึก (TD-08) และ validation เดียวกัน (FR-HIST-06)
- แสดงเพิ่ม: เวลา, ผู้สร้าง/ผู้แก้ไขล่าสุด และปุ่มลบ (แยกด้านซ้าย สีอันตราย)
- ปุ่ม "บันทึกการแก้ไข" disabled จนกว่าจะมีการเปลี่ยนแปลง
- ส่งเฉพาะ field ที่เปลี่ยน (UF-EDIT-01)

## 3. Feedback & Confirmation

### 3.1 รูปแบบ feedback

| รูปแบบ | ใช้เมื่อ | พฤติกรรม | ARIA |
|---|---|---|---|
| **Button busy** | ระหว่าง request | ข้อความเปลี่ยน ("กำลังบันทึก…"), spinner, disabled และขนาดปุ่มคงที่ | `aria-busy="true"`, `aria-disabled` |
| **Toast success** | ผลสำเร็จที่ไม่ต้องทำอะไรต่อ | อยู่ 5 วินาที † หยุดนับเมื่อ hover หรือ focus, ปิดได้ และมีปุ่มเลิกทำได้ถ้ามี | `role="status"` |
| **Toast error** | ผลล้มเหลวของ action ที่ไม่ได้อยู่ในฟอร์ม (เช่น สร้างบิล) | **อยู่จนกว่าผู้ใช้ปิด** + ปุ่ม "ลองอีกครั้ง" | `role="alert"` |
| **Inline banner** | error ของฟอร์มหรือส่วนของหน้า | อยู่บนสุดของส่วนนั้น และหายเมื่อแก้หรือลองใหม่สำเร็จ | `role="alert"` |
| **Field error** | validation | ใต้ช่อง | `aria-describedby` |
| **Confirm dialog** | §3.2 | modal + focus trap | `role="alertdialog"` |
| **Status bar** | offline, realtime หลุด, environment | แถบบนจอ | `role="status"` |

ข้อความทุกชนิด: ภาษาไทย, บอก **อะไรเกิดขึ้น + ทำอะไรต่อ** และไม่แสดงข้อความภายในระบบ (ER-17) แต่ error ที่มาจาก server แสดง **รหัสอ้างอิงสั้น** สำหรับแจ้งผู้ดูแล

### 4.1 Loading
- ครั้งแรก: skeleton ที่ขนาดเท่าของจริง (กัน CLS) และหลังจากนั้น refresh แบบเงียบ (คงข้อมูลเดิม + สถานะ "กำลังอัปเดต…" ที่ header)
- ถ้าโหลดเกิน 10 วินาที † แสดง "ใช้เวลานานกว่าปกติ…" + ลองใหม่
- ไม่บล็อกทั้งหน้าเพราะส่วนที่ช้าที่สุด (PP-26)

### 4.2 Offline
- ตรวจจาก `navigator.onLine` + ผลของ request ที่ล้มเหลวด้วย network error
- แถบสถานะทั่วแอป "ไม่มีอินเทอร์เน็ต · ข้อมูลที่เห็นอาจไม่ใช่ล่าสุด"
- อ่าน: แสดงข้อมูลที่โหลดไว้แล้ว + เวลา ณ ที่โหลด
- เขียน: ปุ่ม disabled + เหตุผล และฟอร์มเก็บ draft โดยไม่มี offline queue (นอก scope)
- กลับมาออนไลน์: แถบหาย, refresh ข้อมูลอัตโนมัติ และ **ไม่ส่ง** ฟอร์มอัตโนมัติ

### 4.3 Environment badge (A-08)
Preview หรือ local แสดงแถบถาวร "ทดสอบ · ไม่ใช่ข้อมูลจริง" ทุกหน้ารวม `/login` ส่วน production ไม่แสดง

| Pull-to-refresh | ปิดใน PWA standalone และหน้า `/add` (`overscroll-behavior-y: contain`) แล้วใช้ปุ่มรีเฟรชแทน ส่วนใน browser ปกติถ้าเกิดขึ้น draft ยังอยู่ (FR-PLAT-02) |
| Scroll position | กลับจาก dialog แล้วตำแหน่งเลื่อนเดิมต้องคงไว้ |
| Swipe | ไม่ใช้ swipe เป็นทางเดียวในการทำ action ใด (เช่น swipe เพื่อลบ) |
| Pinch zoom | เปิดใช้ (NFR-A11Y-02) |
| Long press | ไม่ใช้ |
