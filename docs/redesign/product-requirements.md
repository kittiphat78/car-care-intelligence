## 3. Users, Roles & Permission Boundaries

### 3.1 ผู้ใช้ (Personas)

| Persona | หลักฐาน | การใช้งาน |
|---|---|---|
| **เจ้าของร้าน** (วัยผู้ใหญ่) | README "ผู้ใช้งานวัยผู้ใหญ่", "ธุรกิจครอบครัว" [V] และ prompt AI เดิมเรียกผู้ใช้ว่า "คุณแม่" (`insights/route.ts:93`) [I] | ดู dashboard, ทวงหนี้, export ให้ธนาคาร [I] |
| **ผู้บันทึกงานหน้าร้าน** (พนักงานหรือสมาชิกครอบครัว) | `created_by_email`/`updated_by_email` และ UI "เพิ่มโดย" กับ "แก้ไขล่าสุดโดย" แสดงว่ามีผู้ใช้หลายบัญชี [V] แต่จำนวนและบทบาทจริง [U] | บันทึกรายรับ/รายจ่ายต่อเนื่อง (bulk) [V] |
| **เต็นท์รถ / ลูกค้าเครดิต** (ภายนอก ไม่ login) | `customer_name`, `payment_status`, sublabel "ขัดสี — เต็นท์รถ" (`IncomeForm.tsx:68`) [V] | รับบิลเงินสด PDF |
| **ธนาคาร** (ภายนอก ไม่ login) | Export โหมด "ฉบับให้ธนาคารดู" [V] | รับไฟล์ Excel |

อุปกรณ์: **มือถือ + tablet + PC บน Chrome และ Safari** [V — เจ้าของยืนยัน D-12] ส่วนรุ่น, OS และจำนวนเครื่อง [U]

### 3.2 Roles ปัจจุบัน [V]

| Role | สิทธิ์ |
|---|---|
| Anonymous | เห็นเฉพาะ `/login` (middleware) แต่สิทธิ์จริงต่อ DB ขึ้นกับ RLS [U] |
| Authenticated | **ทำได้ทุกอย่าง** ทั้งดู, เพิ่ม, แก้, ลบ, เคลียร์หนี้, export และออกบิล |

### 3.3 Permission boundaries สำหรับ redesign

- **ข้อกำหนดขั้นต่ำ (ไม่ขึ้นกับการตัดสินใจ):** ทุกการอ่านเขียนต้องบังคับด้วย RLS สำหรับ `authenticated` เท่านั้น, `anon` ต้องไม่มีสิทธิ์ใน `records`/`expenses` และ audit fields ต้องถูกกำหนดฝั่ง DB (NFR-SEC-01..04)
- **การแยก role (เจ้าของ vs ผู้บันทึก)** เช่น จำกัดการลบ, การเคลียร์หนี้ หรือ export **ยังไม่มีหลักฐานว่าต้องการ** จึงไม่กำหนดเป็น requirement → Q-01
- ถ้าไม่ได้ตัดสินใจ: **คงพฤติกรรมเดิม** (ทุก user ที่ login เท่ากัน) ใน MVP

## 5. Non-functional Requirements

ค่าเป้าหมายที่มีเครื่องหมาย † เป็น **ค่าที่เสนอ** และต้องยืนยันใน Q-10 ก่อน Step 09

### Security (SEC)

| ID | Requirement | วิธีตรวจ |
|---|---|---|
| NFR-SEC-01 | RLS เปิดบน `records` และ `expenses` โดย `anon` ไม่มีสิทธิ์ใด ๆ | SQL `pg_tables.rowsecurity`, policy test ด้วย anon key บน **staging** |
| NFR-SEC-02 | ไม่มี service role key หรือ secret ใน client bundle | grep build output + review env |
