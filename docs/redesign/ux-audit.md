# UX Audit — Step 03

> วันที่: 2026-10-14 · ตรวจที่ `7f58eec` (Production candidate) · วิธี: heuristic review จาก source code + คำนวณ contrast จาก design tokens จริง
> ป้ายกำกับ: **[V]** Verified จากโค้ดหรือการคำนวณ · **[I]** Inferred · **[U]** Unknown
> **ยังไม่ได้รันแอปกับข้อมูลจริงหรือทดสอบกับผู้ใช้** เพราะต้องใช้ staging และบัญชีทดสอบ (S03-01) ดังนั้น metric เชิงพฤติกรรม (เวลา, จำนวนแตะ) และ Lighthouse จึงเป็น **NOT RUN** (§6)
> Severity: 4 = ทำให้งานล้มหรือข้อมูลผิด · 3 = ทำให้ช้าหรือสับสนมาก · 2 = ระคายเคือง · 1 = ความสวยงามหรือความสม่ำเสมอ

## 1. สรุป

ระบบเดิมมีฟีเจอร์ครบสำหรับงานหลัก และมีจุดดีที่ควรคงไว้ (§5) แต่ **UX ขัดกับกลุ่มผู้ใช้หลัก (วัยผู้ใหญ่)** ใน 4 แกน:

1. **อ่านยาก:** ตัวอักษร 10–12px 42 จุด และสีข้อความรอง (`--text-tertiary`) **ไม่ผ่าน contrast ทั้ง 2 theme** [V]
2. **ข้อมูลสำคัญไม่อยู่ในตำแหน่งที่หาง่าย:** รายการวันนี้อยู่ล่างสุดของ dashboard (หลังกราฟและตารางลูกค้า) และสมุดทวงหนี้เข้าได้ทางเดียวคือการ์ดแจ้งเตือน [V]
3. **พฤติกรรมไม่คาดคิด:** reload แล้วถูกพากลับหน้าแรกและฟอร์มหาย, การ์ดดูเหมือนกดได้แต่กดไม่ได้ และแก้ไขแล้ววันที่เปลี่ยนเอง [V]
4. **ไม่รองรับ PC:** layout คอลัมน์เดียว `max-w-2xl` + bottom nav บนทุกขนาดจอ [V] ทั้งที่ PC อยู่ในอุปกรณ์เป้าหมาย (D-12)

## 4. Audit ราย Route

- ✅ label ผูกกับ input, `autocomplete` ถูกต้อง, ปุ่มแสดงรหัสผ่าน, ข้อความ error ไม่บอกว่าอีเมลมีอยู่หรือไม่
- ❌ PP-28 · ปุ่มเปลี่ยน theme ไม่มีในหน้านี้ (ไม่จำเป็น) · ไม่มีคำแนะนำกรณีลืมรหัสผ่าน (Q-15)

### `/` Dashboard
- ✅ ตัวเลขใหญ่, empty state ของแต่ละส่วน, realtime และ skeleton
- ❌ PP-04, PP-05, PP-14, PP-21, PP-26, PP-30 · อากาศอยู่เหนือตัวเลขเงิน ทั้งที่ priority (P2) ต่ำกว่า (FR-DASH-08)

### สมุดทวงหนี้ (modal บน `/`)
- ✅ จัดกลุ่มตามลูกค้า, จำนวนวันค้าง, ยอดรวมใหญ่ชัด และปุ่มสร้างบิลมีสถานะกำลังสร้าง
- ❌ PP-06, PP-15, PP-20, PP-25 · ปุ่มสร้างบิลและเคลียร์ยอดมีน้ำหนักเท่ากัน ทั้งที่เคลียร์ยอดเป็น action ที่เปลี่ยนข้อมูล

### `/add`
- ✅ ปุ่มเลือกแทนการพิมพ์, quick-pick ลูกค้า, ลูกค้าประจำ, คงค่าระหว่างบันทึกต่อเนื่อง, กันกดซ้ำ, Zod validation และ input `inputMode="numeric"`

- ✅ สรุปยอด, ค้นหาทะเบียนหรือชื่อ, กรองวันที่และประเภท, จัดกลุ่มตามวันพร้อมยอดรายวัน และแสดงผู้สร้าง/แก้ไข

### Edit modal
- ✅ ยืนยันลบ 2 ขั้น, audit trail และ bottom sheet บนมือถือ
- ❌ PP-01, PP-20, PP-22 · ไม่มี validation (ER-05) · ประเภทรถและยี่ห้อหน้าตาต่างจากหน้า Add (TD-08)

### Export modal

- ❌ PP-02, PP-29 · ไม่มี try/catch (ER-07) · ไม่บอกล่วงหน้าว่าจะได้กี่รายการ

### Error / 404

- ❌ หน้า error ไม่มีรหัสอ้างอิงสำหรับแจ้งผู้ดูแล (`error.digest` ไม่ถูกแสดง)

## 5. สิ่งที่ควรรักษาไว้ (ห้ามหายใน redesign)

1. การเลือกด้วยปุ่มใหญ่แทนการพิมพ์ (ประเภทงาน, ประเภทรถ, ยี่ห้อ, สถานะ และปุ่มลัดรายจ่าย)
2. "บันทึกแล้วทำต่อ" ที่จำค่าที่เลือกไว้
3. Quick-pick ชื่อลูกค้า และการแจ้ง "ลูกค้าประจำ ครั้งที่ N"
4. ตัวเลขเงินขนาดใหญ่และยอดรวมรายวันในประวัติ
5. จัดกลุ่มหนี้ตามเต็นท์ + จำนวนวันค้าง + สร้างบิล
6. ภาษาไทยทั้งหมด และปี พ.ศ.
7. Bottom navigation 3 จุดหมายหลัก ที่มีปุ่ม "บันทึก" อยู่ตรงกลาง (ความคุ้นเคยของผู้ใช้ CR-09)
