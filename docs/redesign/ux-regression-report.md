## 2. ปัญหาที่พบและแก้ใน Step 09

### U-01 — บันทึกไม่สำเร็จ แต่บนมือถือมองไม่เห็นข้อความ · High (UX) · แก้แล้ว

- **พบโดย:** ภาพหน้าจอ: ให้ฐานข้อมูลตอบ 500 แล้วกด "บันทึก" ที่ล่างฟอร์ม → หน้าจอเหมือนเดิมทุกอย่าง ไม่มีอะไรบอก [V]
- **สาเหตุ:** ข้อความ "บันทึกไม่สำเร็จ" (`role="alert"`) แสดงที่ **บนสุด** ของฟอร์ม ขณะที่ผู้ใช้อยู่ล่างสุดที่ปุ่ม จึงอยู่นอกจอ · screen reader อ่านได้ แต่คนที่ดูจอไม่รู้ว่าบันทึกไม่สำเร็จ ขัด IS-1 ("บอกผลเสมอ") [V]
- **ผลกระทบ:** คนบันทึกอาจคิดว่าบันทึกแล้วแล้วไปทำอย่างอื่น รายการจึงหาย (ข้อมูลยังอยู่ในฟอร์ม แต่ผู้ใช้ไม่รู้) [I]
- **แก้:** `RecordEditor.tsx` ย้าย focus ไปที่ข้อความทุกครั้งที่บันทึกล้ม (เบราว์เซอร์เลื่อนให้เห็น) แบบเดียวกับ `FormErrorSummary` ของการกรอกไม่ครบ
- **ทดสอบซ้ำ:** unit "keeps the form after a network failure…" ตรวจเพิ่มว่า focus อยู่ที่ข้อความ ✅ [V] · ภาพหน้าจอ Pixel 7 (ฐานข้อมูลตอบ 500): หน้าเลื่อนขึ้นแสดง "บันทึกไม่สำเร็จ · ระบบขัดข้องชั่วคราว (รหัส …)" ทันที ข้อมูลยังอยู่ในฟอร์ม ✅ [V]

### A-02 — ปุ่ม "บันทึกรายจ่าย" ล้นขอบจอที่ 320px · Medium · แก้แล้ว

- **พบโดย:** ตรวจ reflow 320px (WCAG 1.4.10) + ภาพหน้าจอ: ปุ่มหลักยื่นถึง x=336 บนจอ 320 ตัวหนังสือโดนตัด [V]
- **แก้:** `ActionBar` เปลี่ยนจาก grid 2 คอลัมน์เป็น flex ที่ขึ้นบรรทัดใหม่ได้: ปกติเหมือนเดิม (ปุ่มรองตามความยาวข้อความ ปุ่มหลักเต็มที่เหลือ) ถ้าจอแคบจนไม่พอ ปุ่มหลักลงบรรทัดใหม่เต็มความกว้าง
- **ทดสอบซ้ำ:** วัดที่ 320 / 360 / 412 / 1440px ทั้งฟอร์มรายรับและรายจ่าย: ไม่มีอะไรเลยขอบ · 360px ขึ้นไปตำแหน่งปุ่มเท่าเดิมทุกพิกเซล [V]

## 5. สถานะหน้าจอ (Loading / Empty / Error / Success / Offline) บนมือถือ [V]

| สถานะ | หน้าที่ตรวจ | ผล |
|---|---|---|
| Loading | ภาพรวม, ค้างชำระ, ประวัติ (หน่วงข้อมูลไว้) | skeleton ตามรูปร่างของเนื้อหา หัวข้อและปุ่มขึ้นก่อน · **ก่อนแก้หน้าภาพรวมขยับทั้งหน้าเมื่อข้อมูลมา (CLS 0.545)** · หลังแก้ skeleton สูงเท่าของจริงทุกการ์ด CLS 0.002 (O-08…O-10, `performance-audit.md`) |
| Error (ฐานข้อมูลตอบ 500) | ภาพรวม, ค้างชำระ, ประวัติ | ข้อความไทย + รหัสอ้างอิง + "ลองอีกครั้ง" เฉพาะการ์ดที่ล้ม · ไม่แสดง ฿0 |
| Error ตอนบันทึก | `/add` | ก่อนแก้: มองไม่เห็น (U-01) · หลังแก้: เลื่อนไปที่ข้อความ (ภาพหน้าจอยืนยัน) |
| Empty | ภาพรวม, ค้างชำระ, ประวัติ (บัญชีที่ไม่ใช่สมาชิก) | ข้อความบอกชัดว่าไม่มีรายการในช่วงนั้น |
| Offline | `/add` | แถบบนสุด + ข้อความเหนือปุ่ม + ปุ่มบันทึกปิดและเขียน "รอเชื่อมต่อ" · ข้อมูลที่กรอกยังอยู่ |
| Success | `/add` → ภาพรวม | toast "บันทึก … แล้ว" + ไฮไลต์รายการที่เพิ่งบันทึก |
